KEY FINDINGS
================================================================================

1. ARCHITECTURE
   - Layered design: LookupContext → MavenContext → ResidentMavenContext
   - Clear separation: environment → container → execution → cleanup
   - Event-driven with extensible listener system
   - Dependency injection via Plexus for Maven components

2. EXECUTION FLOW (4 Phases, 26 Steps)
   Phase 1 - Environment Setup (9 steps):
     validate → pushCoreProperties → pushUserProperties → setupGuiceClassLoading
     → configureLogging → createTerminal → activateLogging → helpOrVersionAndMayExit
     → preCommands
   
   Phase 2 - Container & DI Setup (7 steps):
     container → postContainer → pushUserProperties(2nd) → lookup
     → init → postCommands → settings
   
   Phase 3 - Maven Execution (4 steps):
     prepareMavenExecutionRequest → toolchains → populateRequest → doExecute
   
   Phase 4 - Cleanup (6 steps):
     context.close() with reverse-order closeables cleanup
     + container shutdown + classloader restoration + properties restoration

3. OPTIONS MANAGEMENT
   - Layered precedence: CLI (1) > @file (2) > maven.config (3)
   - Parsed by MavenParser using CommonsCliOptions
   - Combined via LayeredMavenOptions
   - 50+ individual options with specific behaviors

4. REQUEST BUILDING
   - DefaultMavenExecutionRequest created with specific defaults
   - Settings populate repositories, servers, proxies, mirrors, profiles
   - Options populate goals, failure behavior, offline, snapshots, checksums
   - Listeners selected based on quiet/interactive/logfile flags
   - Project/profile activation parsed with +/-/? prefixes
   - Threading calculated from threads option or builder override

5. ERROR HANDLING
   - DefaultExceptionHandler converts exceptions to ExceptionSummary tree
   - Recursive logSummary with ANSI color preservation
   - Resume hints calculated: -r (resumable) or -rf :artifactId/-rf groupId:artifactId
   - Artifact ID collision detection for accurate resume selectors
   - Help references with numbered [Help N] format

6. LISTENER ARCHITECTURE
   Transfer Listeners (selectable):
     - QuietMavenTransferListener (quiet/CI/noProgress)
     - SimplexTransferListener(ConsoleMavenTransferListener) (interactive)
     - Slf4jMavenTransferListener (batch/logfile)
   
   Execution Listeners (chained):
     - ExecutionEventLogger (core logging)
     - Optional EventSpyDispatcher chain
     - LoggingExecutionListener wrapper with BuildEventListener

7. THREADING & CONCURRENCY
   Single-threaded by default (safe)
   Supports format: --threads N or --threads NC (multiplier)
   Sets builderId to "multithreaded" when threads > 1
   SimplexTransferListener provides thread-safety for progress meter

8. RESIDENT MODE
   ResidentMavenInvoker shares Plexus container and Maven instance
   Uses ConcurrentHashMap for persistent storage
   Creates shadow contexts when invokerRequest differs
   Reuses: containerCapsule, lookup, eventSpyDispatcher, maven
   Used by: mvnsh (Maven shell)

KEY INSIGHTS SUMMARY
================================================================================

1. MavenInvoker is a sophisticated orchestrator managing:
   - Complex lifecycle: environment → container → execution → cleanup
   - Layered options with clear precedence (CLI > @file > maven.config)
   - Rich event-driven architecture for extensibility
   - Careful resource management with reverse-order cleanup
   - User-friendly error handling with resume hints

2. Design emphasizes:
   - Separation of concerns (clear phase boundaries)
   - Extensibility (listeners, event spies, property contributors)
   - User experience (helpful errors, ANSI colors, progress)
   - Resource safety (try-with-resources, exception aggregation)

3. Architecture supports:
   - Fresh invocation per build (MavenInvoker)
   - Persistent Maven instance (ResidentMavenInvoker for mvnsh)
   - Multi-threaded builds with thread-safe listeners
   - Both interactive (console) and batch (file) modes

4. Critical patterns:
   - Layered context inheritance for specialization
   - Listener chain for composable logging
   - Shadow context for multi-invocation sharing
   - Recursive exception summary for user-friendly messages
